## v4.8.25 live fixes

### MOB ATTACK UI

- Fixed HEDEF/SKILL/SCROLL controls leaking into each other.
- `RefreshMobLists()` no longer re-shows skill rows while HEDEF is active.
- Target rows, status text, save controls and skill rows were separated so they do not overlap.
- Added responsive child-control layout scaling rather than relying only on font scaling.
- Tested layout at 100%, 125%, 150% and 200% DPI/scale scenarios.

### PRIEST category

- Fixed the missing PRIEST sidebar owner-draw category condition.
- PRIEST now uses the same normal burgundy category styling as ROGUE/WARRIOR/ATTACK/MOB ATTACK; it no longer receives the unrelated gold/orange action-button appearance.

### MOB visual registration / anti-aliased red text

- Relaxed the old overly strict red-name threshold so thin/anti-aliased Knight Online red nameplates can be learned and detected.
- Neutral gray/noise remains rejected.
- Strong red and dim anti-aliased red scenarios both pass.
- Registration still requires a meaningful red name/nameplate signal; it does not blindly accept arbitrary crops.

### MOB target selection correctness

Selection is fail-closed. The program does not authorize R or MOB skills merely because a mouse click or Z key was sent.

Flow:

1. Scan learned MOB nameplate candidates.
2. Try mouse selection first using bounded offsets around the learned nameplate location.
3. Require selected-target HP visibility **and** target-header match.
4. If the learned image/nameplate is occluded or cannot be clicked successfully, use bounded Z fallback.
5. Z fallback must again satisfy target HP + target-header verification.
6. Only a confirmed target may enable MOB R chase and MOB skill rotation.

Validated scenarios include wrong first click, empty click, occluded mobs, multiple candidates, normalized names, exact-name mode, partial-name mode, range limits and all seven target-record slots.

### MOB chase / attack safety

- MOB chase remains R-driven; W is not introduced as a MOB chase command.
- R and MOB skills require `g_mobTargetConfirmed`.
- A lost/changed target clears confirmation and triggers reacquisition rather than continuing to attack an unverified target.
- Range/leash remains fail-closed when a saved farm center requires position confirmation.

### Existing modules preserved

Static source comparison protects the established runtime bodies that were not intended to be rewritten by the v4.8.25 live fix, including the existing Rogue/Minor/Cure/Attack/Vitals/MOB Scroll/Warrior and related stable runtime paths covered by the regression gates.
